# 글쓰기 규칙 (AI 티 줄이기)

새 글을 쓰거나 고칠 때 이 파일을 먼저 읽는다. 2026-11-12에 [slop-rewrite](https://github.com/byungjunjang/slop-rewrite)의 원칙과 장피엠 문체 가이드, 동원의 취향 규칙으로 기존 글 17편을 다듬었다. 아래는 그때 쓴 규칙을 줄인 것이다.

## 지키는 것 (어기지 않는다)

1. 새 사실 금지. 숫자·이름·인용·출처·주장을 지어 넣지 않는다. 원문 숫자로 계산한 값도 새 사실이다.
2. 고정 구역 보존. 표(`Table`), 코드, 원문 인용, `Moonlight AI 답변: “…”` 인용은 글자 그대로 둔다.
3. 뜻 뒤집기 금지. 부정·조건·시제·확정 수준(「반론이 나왔다」를 「반박되었다」로 올리지 않는다)·단위를 바꾸지 않는다.

## 이 사이트의 취향

- 본문 말끝은 합쇼체(-습니다)다. 퀴즈 질문은 「~입니까?」, 안내는 「~해 보십시오」, 오답 문구는 「오답입니다.」. 질문·답변 기록 안의 해라체 메모와 직접 인용은 그대로 둔다.
- 한 문장에 한 생각. 관형절 사슬과 종속절 중첩은 끊는다. 능동형으로 쓴다.
- 한 개념은 한 용어로 부른다(예: 「고정 길이 벡터」를 「입력 요약」, 「고정 벡터」로 바꿔 부르지 않는다).
- 전문용어는 처음 나올 때 「한글(영어, 짧은 뜻)」으로 푼다.
- 「(예시)」, 「(논문 밖)」, 「(추정)」, 「미확인」, 쪽·절·식 표시(p.5, §2.4, 식 (3))는 지우지 않는다.
- Moonlight 앱 안 AI의 출력은 「Moonlight AI 답변」으로 쓴다.
- 「한 장면 비유」 절과 「비유의 한계」 상자는 구성이라 남긴다. 문장 속 장식 비유만 고친다.
- 줄표(—)로 문장을 잇지 않는다. 숫자 범위의 「–」(식 (1)–(9))는 쓴다. 이모지는 쓰지 않는다.
- 확인하지 못한 일을 끝난 일처럼 쓰지 않는다.

## 지우는 것 (AI 티)

- 헛기침과 예고: 「정리하면 이렇습니다」, 「여기서 핵심은」, 「다음 절에서 하나씩 떼어 봅니다」처럼 내용 없이 예고만 하는 문장
- 요약·교훈 마무리: 「결론적으로」, 문단 끝 교훈 한 줄
- 콜론 극적 공개(「이 화면에서 볼 것: …」)와 질문형 제목(「~할까요?」). 라벨 콜론(「1단계:」)은 둔다
- 수사 설정: 「떠올려 보세요」, 「다시 생각해 보세요」
- 「A가 아니라 B」 남용, 부정 나열 3연
- 평가어(「단단한」, 「혁신적인」), 무생물 주어에 사람 동사, 뜻이 빈 광의 동사, 번역투
- 문두 접속부사(「또한」, 「따라서」)는 지워 보고 뜻이 통하면 뺀다

## 고친 뒤 확인

- `npm run build` 오류 0
- 위젯이 있는 글은 버튼·슬라이더를 움직여 페이지 오류가 없는지 본다
- 절 제목을 바꾸면 `TableOfContents`의 같은 `id` 항목 `label`도 맞춘다
