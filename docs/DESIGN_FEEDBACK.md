# 디자인 피드백 (모든 글에 적용)

새 글을 쓰거나 디자인을 고치기 전에 이 파일을 먼저 읽는다. 아래 "반드시 지킬 규칙"은 모든 글에 적용한다.

## 반드시 지킬 규칙

### R1. 흐름도 화살표는 짧게 (선 16px)
- 파일: `src/components/canvas/Diagram.tsx`
- 값: `RANK_GAP = 32`, `CLEAR = 8` → 보이는 선 길이 = 32 − 8 × 2 = 16px
- 이전 값 `RANK_GAP = 56`(선 40px)은 너무 길다는 피드백을 받았다.

### R2. 목차는 화면 왼쪽 끝 (현재 배치 유지)
- 파일: `src/components/canvas/canvas.css`
- 값: `--cv-toc: 220px`, `--cv-main: 700px`
- 그리드: `minmax(var(--cv-toc), 1fr) minmax(0, var(--cv-main)) minmax(0, 1fr)` → 목차는 왼쪽 끝, 본문은 화면 가운데
- 목차: `position: sticky; top: 28px; padding-top: 60px`
- 1040px 미만 화면에서는 목차가 제목 아래로 내려간다.
- 튜링 글(쿨톤, Q&A 8개, 목차 왼쪽 끝)이 승인된 기준이다.

### R3. 흐름도가 모바일 폭을 넘지 않게
- 파일: `src/components/canvas/Diagram.tsx`, `src/components/canvas/canvas.css`
- 값: 화살표 이름표 줄바꿈 폭 `EDGE_LABEL_MAX = 56`(이전 160), 흐름도 바깥 여백 `PAD = 12`(이전 24), 560px 이하에서 그림 카드 안쪽 여백 `.cv-card { padding: 12px }`(이전 20)
- 결과: LLM 글 흐름도가 390px 화면에서 옆으로 넘치지 않고 이름표 "아니오: 글 끝에 붙이고 다시"가 4줄로 다 보인다. 흐름도 배치는 빌드 때 한 번 정해지므로 데스크톱에서도 같은 4줄이다.
- 그래도 넘치는 표·흐름도·히트맵은 가장자리 스크롤 그림자(`--scroll-shadow`)로 "옆에 더 있다"를 보여 준다.

### R4. 흐름도 칸은 1px 테두리만 (왼쪽 굵은 색 선 없음)
- 파일: `src/components/canvas/Diagram.tsx`
- 값: 설명이 붙은 칸도 `border: 1px solid var(--border-default)`만 쓴다. 예전의 왼쪽 4px 회색 선(`borderLeft`)과 그 색을 고르던 `accent()`는 지웠다.

## 피드백 기록

| 날짜 | 피드백 | 반영 | 규칙 |
|---|---|---|---|
| 2026-11-02 | 흐름도 단계 사이 화살표가 너무 길다 | RANK_GAP 56 → 32 (선 40px → 16px) | R1 |
| 2026-11-02 | 목차는 지금 배포된 튜링 글처럼 왼쪽 끝에 둔다 | 현재 값 유지 | R2 |
| 2026-11-02 | 흐름도 이름표가 모바일에서 잘린다 | 이름표 폭 160→56, PAD 24→12, 모바일 카드 여백 20→12, 스크롤 그림자 | R3 |
| 2026-11-02 | 흐름도 칸 왼쪽에 붙은 회색 선을 없애고 깔끔한 칸으로 | 왼쪽 4px 회색 선 제거 | R4 |

## 운영 방법
1. 새 피드백은 "피드백 기록"에 한 줄씩 쌓는다.
2. 같은 요구가 다시 나오거나 모든 글에 해당하면 "반드시 지킬 규칙"으로 올린다.
3. 규칙 값을 바꾸면 이 파일의 값도 함께 고친다.
